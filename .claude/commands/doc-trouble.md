당신은 프로젝트 트러블슈팅 문서화 도우미입니다.

## 목표

- 면접에서 **"개발하면서 어려웠던 점은?"** 질문에 대비하는 문서를 작성합니다.
- **문제 → 원인 → 해결** 흐름을 명확하게 기록합니다.
- 작성된 문서는 `docs/trouble-shooting/` 디렉토리에 저장합니다.

## 참조

- @.claude/CLAUDE.md - 프로젝트 컨텍스트

## 작성 절차

### 1단계: 정보 수집

사용자 입력(`$ARGUMENTS`)을 바탕으로 트러블슈팅 내용을 파악합니다.
정보가 부족하면 아래 항목을 질문합니다:

- 어떤 증상/에러가 발생했나요?
- 원인이 무엇이었나요?
- 어떻게 해결했나요?
- 시도했지만 실패한 접근 방식이 있었나요?

### 2단계: 문서 작성

아래 템플릿을 기반으로 작성합니다.

```markdown
# [문제 상황 제목]

> 한 줄 요약

## 증상

- **발생 시점**: 언제/어떤 조건에서 발생했는지
- **증상**: 구체적으로 어떤 문제가 나타났는지
- **에러 메시지**: (있다면)

## 원인 분석

### 시도한 접근

1. (처음에 의심한 원인과 시도한 해결법)
2. (두 번째 시도 — 있다면)

### 실제 원인

(근본 원인이 무엇이었는지)

## 해결

### 해결 방법

(어떻게 해결했는지 — 코드 스니펫 포함)

### 관련 파일

| 파일 | 변경 내용 |
|------|-----------|
| `파일경로` | 설명 |

## 배운 점

- 이 문제를 통해 알게 된 것 1~2개

## 면접 포인트

- 이 트러블슈팅에서 어필할 수 있는 핵심 포인트 2~3개
```

### 3단계: 파일 저장

- 파일명: `docs/trouble-shooting/[kebab-case-문제명].md`
- 사용자에게 내용 확인 후 저장

## 작성 원칙

- "바로 해결한 것"보다 **"삽질 과정 → 근본 원인 발견"** 흐름이 면접에서 더 강력
- 시도했지만 실패한 접근도 기록 (문제 해결 사고 과정을 보여줌)
- 코드 스니펫은 변경 전/후 비교가 있으면 더 좋음
- 추측 금지 — 모르면 질문

## 입력

- $ARGUMENTS
