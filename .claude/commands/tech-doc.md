## 작성 절차

### 1단계: 전체 분석

1. CLAUDE.md의 프로젝트 개요, 의사결정 로그, 기능 명세를 숙지
2. `docs/` 하위 모든 문서를 읽고 핵심 내용 추출
3. `src/` 코드를 분석하여 실제 구현 상태 파악
4. git log를 통해 개발 히스토리 파악

### 2단계: 사용자 확인

분석 결과를 바탕으로 아래 항목을 사용자에게 확인합니다:

- 문서에 특별히 강조하고 싶은 기술 포인트가 있는지
- 빠뜨리면 안 되는 고민/트러블슈팅이 있는지
- 대상 기업/직군에 맞춘 톤 조정이 필요한지

아래 템플릿을 기반으로 작성합니다. 각 섹션은 실제 코드/문서 내용을 반영하여 구체적으로 작성합니다.

- "왜 이런 UX를 선택했는지" 근거를 반드시 포함

## 작성 원칙

### 톤 & 스타일

- **면접관이 읽는 문서** — 전문적이면서도 읽기 쉽게
- 기술 용어는 정확하게, 설명은 간결하게
- "~했습니다" 체 사용 (경어체, 과도하게 딱딱하지 않게)

### 내용 원칙

- **"왜"를 반드시 포함** — 모든 기술 선택에 근거가 있어야 함
- **구체적 수치/코드** — 추상적 설명보다 실제 코드 스니펫과 수치
- **고민 과정 노출** — 바로 정답을 낸 것이 아니라 비교/검토 후 결정했음을 보여주기
- **트레이드오프 인지** — 장점만 나열하지 않고 감수한 단점과 대응 방법도 기술
- **실패/삽질 기록** — 트러블슈팅에서 시도했지만 실패한 접근도 포함 (문제 해결 능력 어필)

### 금지 사항

- 코드 전체를 붙여넣는 행위 (핵심 로직만 발췌)
- 추측으로 작성 (모르면 사용자에게 질문)
- docs/ 문서를 그대로 복붙 (종합/재구성하여 하나의 흐름으로)
- 뻔한 내용 반복 ("React를 사용했습니다" 수준의 설명)
